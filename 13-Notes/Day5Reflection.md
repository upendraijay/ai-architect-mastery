## Design Patterns — Interview Questions & Answers

### Q1. What is a Design Pattern?

A design pattern is a proven way of organizing classes and objects to solve a common software design problem.

---

### Q2. What problem does a Factory solve?

Factory solves the problem of having duplicated or scattered object-creation logic by moving object creation to one place.

---

### Q3. Factory vs Builder — what's the difference?

Factory centralizes **object creation**, while Builder simplifies the **construction of a complex object**.

---

### Q4. Why shouldn't we use Design Patterns everywhere?

Design patterns should solve a real design problem. Using them everywhere makes the code more complex, harder to understand, and can add unnecessary classes and abstractions.

---

### Q5. Why can Singleton be dangerous?

Singleton can be dangerous because it introduces **global shared state and hidden dependencies**, making the code harder to test and maintain.

---

### Q6. Which pattern did you find most useful?

Factory Pattern was the most useful for me because it clearly showed me how to separate object creation from business logic.

---

### Q7. Which pattern do you think is overused?

Singleton is a pattern I think is often overused. It can hide dependencies and make testing harder. In many cases, **Dependency Injection** is a cleaner alternative.
